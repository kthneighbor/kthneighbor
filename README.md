# Valentin Kotov

I build agentic and data systems, the infrastructure that contains them, and the governance that lets them survive a security review rather than a demo. I come from nearly a decade of enterprise data and AI delivery (and years of various other work before that, such as full-stack web development in the early 2010s). Since 2017, my focus was mainly on the Databricks and Azure platforms, infrastructure as code, DataOps and MLOps - always embedded in client delivery teams, and in one case leading a consultancy's data practice.

The work has one shape across all of it: build the thing that isn't there yet, then hand it over. That job is bounded by nature - something only needs standing up once.

German, based in Uruguay (GMT-3, full overlap with US business hours), working globally through [Salix Austral](https://salixaustral.com). My own path ran through Western and Central Europe, the Gulf, and now Latin America; my clients have been Western multinationals.

## What I run that isn't here

**Hoopoe**, a multi-agent workflow management harness covering the full software-development, backlog management and DocOps lifecycle in a strictly governed manner. It has been in daily production use (for my own closed projects, not for a client). Its architecture I occasionally discuss on LinkedIn, the harness itself I am keeping proprietary for now.

**StudioOS**, likewise. Terraform-defined platform for running agent instances under isolation, on Hetzner. Defence in depth rather than a perimeter - the design assumes the agent is untrusted while still letting it do useful work. Infrastructure as code end to end, including teardown and reproducibility. Internal tooling rather than meant to be used by others, so the code stays closed.

Client work is absent because practically all my delivery has run though consulting contracts - those systems are owned by these various clients, not me. Most of the last decade's code sits in repositories I don't own.
